# vimmed v0.9.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build vimmed v0.9.0, a one-file-per-process markdown editor for macOS and Linux with moon_edit's vim editing and in-place rendering, inside the feature spec's start-up and keystroke thresholds.

**Architecture:** A Rust workspace. `editor-core` holds every behaviour (document, markdown, reveal, vim, commands, files, config, tokens) and has no GUI or font dependency. `editor-render` lays out and rasterises into one RGBA buffer and reports damage as row ranges. Two thin shells present that buffer: AppKit through objc2 with double-buffered IOSurfaces, and GTK4 with one texture per 128 px strip. A libc-only launcher starts the window process in its own session and waits on it.

**Tech Stack:** Rust (edition 2024, toolchain pinned, 1.92 or later), cosmic-text 0.19 behind an internal layout trait, tiny-skia 0.12, swash, tree-sitter 0.27 with tree-sitter-highlight, image 0.25, toml and serde, objc2 0.6 with the objc2 0.3 framework crates, gtk4 0.11 (feature `v4_14`), yeslogic-fontconfig-sys, cargo-deb, cargo-generate-rpm.

**Spec:**
- `docs/superpowers/specs/2026-11-03-vimmed-v0.9-features-design.md` (feature spec: behaviour and thresholds)
- `docs/superpowers/specs/2026-11-03-vimmed-v0.9-stack-design.md` (stack doc: stack, patterns, budget, amended thresholds)
- Prior art: `reports/Vimmed stack best practice.md`. Spike: branch `spike/startup-latency`, read with `git show spike/startup-latency:spike/<path>`. Behaviour reference: `/Users/bawdo/working/projects/moon_edit` (`lib/vim/`, `lib/editor/`, `lib/services/inline_parser.dart`) and its tests under `test/`, which are the source for golden cases.

## Owner decisions recorded while planning (2026-11-03)

These came after both docs were approved. Every task treats them as part of the spec.

1. **Crate names.** The stack doc's `core` crate is called `editor-core`, because `core` collides with Rust's built-in crate. `render` is called `editor-render`. All crate and binary names stay neutral, with no project name in them.
2. **CI is local.** `cargo xtask ci` runs every check, the rename test included. There's no hosted CI config and no remote.
3. **Parity means vim-correct where moon_edit is buggy.** Keep moon_edit's feature set and its deliberate choices (reveal rules, table commands, user-visible strings, literal search). Where moon_edit is buggy, do what vim does, and make every edit undoable. The divergences are listed under "Divergences from moon_edit" below. Each one has a test, so any of them can be vetoed.
4. **Clipboard sync is real** (vim's `unnamedplus`). `y d c x` and `C D` write the system clipboard as well as the unnamed register, and `p P` read the clipboard. Named registers `"a`..`"z` never touch the clipboard.
5. **Compound counts multiply.** `2d3w` deletes 6 words, as in vim. This overrides the feature spec's "Compound counts (`2d3w`) not supported". The help overlay must not claim they are unsupported.

## Global Constraints

Every task's requirements include this section.

- **Platforms:** macOS 14 or later on Apple Silicon (the `NSView.displayLink` floor). Linux under Wayland (primary) and X11 (best effort). GTK 4.14 minimum, built with gtk4-rs feature `v4_14`. Anything from 4.16 or later is checked at run time.
- **Thresholds, at feature complete on both reference machines:**
  - Cold start median at or under 250 ms and p95 at or under 400 ms, measured to the first frame handed to the compositor, on the first run after the file is in the page cache.
  - Keystroke p95 at or under 16 ms, from key event to frame handed to the compositor, from at least 500 manually typed keys.
  - On-glass keystroke p95 recorded alongside, with a target of at or under 2.5 refresh periods (about 42 ms at 60 Hz).
  - First-run cost (empty font cache) measured and reported separately.
- **Linux start-up budget (medians, i7-7700HQ):**

  | Stage | Budget |
  |---|---|
  | Launcher to window `main` | 65 ms |
  | File, parse, config, lock and recovery scan, fonts | 20 ms |
  | GTK init and window | 40 ms |
  | Renderer init to first paint | 80 ms |
  | First layout and raster, hand-off | 40 ms |
  | Total | 245 ms |

  The keystroke budget is our draw at or under 2 ms at p95 and GTK render at or under 4 ms.
- **Shells are thin.** Each of `crates/shell-mac`, `crates/shell-gtk` and `crates/window` stays under 2,500 lines of Rust, counting non-blank lines that aren't comments. All editing and rendering logic lives in `editor-core` and `editor-render`, and is testable without a window.
- **TDD for all core and render logic:** failing test, then the code, then the passing test. Shell code is verified by the smoke test and the measurement runs each task names.
- **One name definition.** `[workspace.metadata.app] name` in the root `Cargo.toml` is the only place the project name appears in source. Every derived form comes from the `app-meta` crate's constants. `cargo xtask ci` fails if the name appears anywhere else under `crates/`, `xtask/`, `packaging/`, `docker/`, `scripts/` or in `README.md`.
- **All colours and styles are tokens.** No literal colour, font family, size, weight, spacing, radius, line height or column width outside `crates/editor-core/src/tokens/`. `cargo xtask ci` checks colour and family literals mechanically. Size literals are a review item on every task that paints.
- **Presentation rules from the stack doc:**
  - Never assign a `CGImage` as layer contents, and never use softbuffer.
  - Damage is a list of separate row ranges, and ranges that don't touch are never merged.
  - GTK: no `GApplication` uniqueness and no libadwaita. Set `GDK_DISABLE=vulkan` at the top of `main` unless the user set `GSK_RENDERER` or `GDK_DISABLE`. Strip `GDK_DISABLE`, `GDK_DEBUG`, `GSK_RENDERER` and every `<ENV_PREFIX>*` variable from processes we spawn.
  - Never scan all system fonts at start-up.
- **Launcher:**
  - Links only libc. It may use `app-meta` and `marks`, which have no runtime dependencies beyond libc.
  - Starts the window with `posix_spawn` and `POSIX_SPAWN_SETSID`. The child's stdio is `/dev/null` and its signal mask and handlers are reset to defaults. Never `PR_SET_PDEATHSIG`, never `pre_exec`, and never infer detaching from `isatty`.
  - Exit codes:

    | Code | Meaning |
    |---|---|
    | the window's own | passed through |
    | 128 + n | the window died from signal n; the launcher prints `<slug>: window ended by signal <n>` to stderr |
    | 130 | SIGINT in the launcher |
    | 2 | usage error, no file, or a directory |
    | 220 | no window came up: the launcher could not start the window binary, or the window found no shell for the platform or its toolkit could not start (ruling R34: the same meaning from either binary, so the launcher passes the window's 220 through) |
    | 221 | launcher and window protocol mismatch, reported by the window |
    | 222 | the launcher lost track of the window: `waitpid` failed with something other than EINTR (owner decision D7; not 1, which is `:cq`). Launcher only: the window never exits 222 |
    | 223 | a bench run's window reached its start-up cap without marking `first_frame`, reported by the window (ruling R28) |

  - The window's own codes are 0 for a normal close, 1 for `:cq` and 143 after SIGTERM (with the recovery copy written). The macOS router (the window started with no path, by Finder or `open`) exits 0 once it has handed its files on, never 220 (R34).
- **Files:**
  - Disk changes only on an explicit write, or autosave when it is enabled.
  - Writes are atomic: a temporary file in the same directory, then fsync, then rename. Writes preserve line endings (LF or CRLF), the trailing-newline state, a UTF-8 BOM and permissions.
  - State lives in `$XDG_STATE_HOME/<slug>/` (default `~/.local/state/<slug>/`) and config in `$XDG_CONFIG_HOME/<slug>/config.toml` (default `~/.config/<slug>/`). Both paths are the same on macOS.
  - State files are TOML or plain text, never JSON.
- **User-visible strings** live in `crates/editor-core/src/strings.rs`. Strings fixed by the spec or moon_edit are copied verbatim: `NORMAL`, `INSERT`, `VISUAL`, `V-LINE`, `changes not saved`, `file changed on disk`, `file no longer on disk`, `read-only`, `reloaded from disk`, `written`, `search wrapped`, `already open in another window (pid N): [o]pen read-only [e]dit anyway [q]uit`, `recovery copy found: [r]estore [d]iscard [c]ompare`, `file changed on disk: [o]verwrite [r]eload [c]ancel`, `<name> (recovery)`, `E37: No write since last change (add ! to override)`, `E492: Not a command: <input>`, `E486: Pattern not found: <pattern>`, `<N> substitutions on <L> lines`, `1 substitution on 1 line`, `<N> matches on <L> lines`, `replace with <r>? [y/n/a/q/l]`. Strings this plan introduces are given in the task that introduces them.
- **Developer environment:**
  - Ask the owner before installing anything: rustup (Task 1), Docker images (Task 17), cargo-deb and cargo-generate-rpm (Task 44), and any new system package. Rust isn't installed on the Mac yet.
  - GUI runs on macOS need the Bash sandbox off, because the sandbox blocks the WindowServer connection. Docker may need it off too, for the socket.
  - Linux compile checks run in Docker (`docker/Dockerfile.check`). Real Linux timings only come from the owner's laptop.
- **Commits:**
  - The owner is asked before the first commit. After that, commit at the end of each task without asking.
  - Never on `main` or `master`, never push, and every commit is gpg-signed. If signing fails, say so loudly and ask the owner to refresh the key.
  - Subjects are past tense and 60 characters or fewer. No agent attribution of any kind.
  - Each commit is three separate tool calls: write the message to `.git/AGENT_COMMIT_MSG` with the Write tool, run `git add <files>` as its own call, then run `git commit -F .git/AGENT_COMMIT_MSG` as its own call. Verify with `git verify-commit HEAD` (expect "Good signature") and `git show --name-only HEAD`.
  - Task "Commit" steps give only the subject.
- **Writing:** Australian English, no em dashes. That applies to code comments, strings and docs alike.

## Review Focus

These are the five inputs the spec implies but never names, and that are most likely to bite. Each has a pinned test in the owning task.

1. **The file is a symlink** (dotfiles managed by stow or chezmoi). `:w` must write through to the target and leave the link in place, never replace the link with a regular file. Test: Task 31 `write_through_symlink_keeps_link`.
2. **The file isn't valid UTF-8** (Latin-1 notes, a binary opened by mistake). It must open read-only with a status message and never be written back lossily. Test: Task 31 `invalid_utf8_opens_read_only_and_refuses_write`.
3. **Grapheme clusters** (emoji ZWJ sequences, decomposed accents, CJK). `h l x`, the cursor, reveal boundaries and `line:column` must step by grapheme, never split one, and never panic on a non-char boundary. Tests: Task 8 `edits_never_split_graphemes`, Task 19 `hl_step_by_grapheme`, Task 20 `x_steps_by_grapheme`.
4. **The window moves between displays of different scale** (Retina to an external 1x panel, or GTK fractional scale 1.5). The frame must be reallocated at the new scale and fully damaged. A stale buffer size must not crash or smear. Tests: Task 11 `resize_to_new_scale_damages_everything`, plus the shell checks in Tasks 15 and 17.
5. **Two windows writing named registers at once.** `"ayy` in one window and `"byy` in another must both survive in the shared state file. Test: Task 23 `concurrent_register_writes_keep_both`.

Also pinned, though outside the five: a failed temporary write (disk full) leaves the original untouched (Task 31 `failed_temp_write_leaves_original`), and a hard-linked file is written in place so the link survives (Task 31 `hardlinked_file_written_in_place`).

### Task 3: Marks log and fixture generator

**Files:**
- Create: `crates/marks/src/lib.rs`, `xtask/src/fixture.rs`
- Test: `crates/marks/src/lib.rs` (unit), `xtask/src/fixture.rs` (unit)

**Interfaces:**
- Produces, in `marks` (deps: `libc`, `app-meta`):
  - `now_ns() -> u64`. Linux uses `CLOCK_MONOTONIC`. macOS uses `CLOCK_UPTIME_RAW`, which is the same base as `NSEvent.timestamp` and `CACurrentMediaTime`, so key events, display-link and mark times share one clock.
  - `init()`, which reads `<P>T0` (ns) or uses the current time, and opens `<P>MARKS` (a log path) for append.
  - `mark(name: &str)`, which records ms since T0. `value(name: &str, ms: f64)`.
